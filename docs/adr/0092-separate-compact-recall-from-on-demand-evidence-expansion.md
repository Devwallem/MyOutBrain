# 分离紧凑知识召回与按需证据展开

V2 使用两阶段召回协议。第一阶段在普通召回预算内返回选中的规范记忆正文，以及必要的 `memory_id`、版本、生命周期状态、适用范围、依赖和冲突标记；来源部分只返回可追溯性、缺失依赖、反证存在等摘要状态和稳定引用句柄，不默认加载证据正文。

当能力引擎无法据此通过可回答性门槛时，可以凭同一 `recall_id` 和指定 `memory_id` 展开所需角色的证据摘录。证据展开使用独立预算，不挤占普通知识召回预算；数据包携带稳定协议版本，使不同入口可以继续同一次运行而无需重复搜索。内部加载过证据不改变渐进披露规则，用户未追问时仍默认只收到结论及必要的知识库来源声明。

## Consequences

普通交互不再为可追溯性反复传输完整来源，高风险、时效性或冲突场景仍可以精确核验。核心需要为短期 `recall_id` 定义过期、幂等展开与审计规则，客户端不得把召回包当作新的长期事实来源。

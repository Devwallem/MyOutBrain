# 以跨入口黑盒场景阻塞 V2 发布

V2 发布门槛以用户可观察的完整场景为主，而不以单元测试覆盖率替代系统验收。发布测试必须验证：空实例初始化及 Codex、OpenCode、Claude Code 入口健康检查；学习信号经 Reflector、批次审阅和批准形成规范记忆；三个入口召回同一知识、声明知识库来源并写入同构召回日志；反证阻止本轮回答并生成提案但不自动改写知识；胶囊裂分、故障恢复和合并保持身份、正文、关系与召回结果；增量迁移包经审计、dry-run 和幂等导入；整库冷快照恢复后通过 `doctor`；次版本兼容读取及未知语义写入拒绝；无 Embedding、无网络、无常驻进程时基础闭环仍可运行。

仓库同时保存固定召回回归集，覆盖名称碰撞、别名、越区全文命中、历史可信知识、冲突与必要依赖。自动胶囊重组和路由维护提交前必须运行该回归集，任何发布候选失败均阻塞 V2。

## Consequences

V2 的可移植性、人工控制和可恢复性成为可执行承诺，而不是文档声明。单元、属性、故障注入和契约测试仍用于快速定位问题，但不能取代端到端黑盒验收。

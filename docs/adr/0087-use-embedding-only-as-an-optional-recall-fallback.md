# 仅将 Embedding 用作可选召回后备

V2 的基础召回不依赖 Embedding：先用知识字典解析稳定身份、名称和别名，再沿知识分区树选择少量相关胶囊，并用 SQLite 全文检索补足正文中的精确术语和细节。各路径只产生 `memory_id` 候选，合并去重后必须通过知识字典读取唯一规范正文。树摘要负责粗粒度路由，不直接作为答案知识。

只有基础召回候选不足、问题表达模糊或需要跨领域语义联想时，才按需启用语义召回器。Embedding 索引可关闭、可删除并重建，不是 V2 安装、普通查询或正确性的硬依赖；即使启用，也只能补充候选，不能成为证据、可信度裁决或知识合并依据。若使用私人内容生成 Embedding，默认仍在本地执行，任何云端发送都需要明确授权。

本决策取代 ADR-0044 和 ADR-0045 将 Embedding 描述为第一阶段默认索引的安排。

## Consequences

小型知识库可以只依靠 SQLite 和分区树工作，降低模型安装、索引迁移与跨客户端兼容成本。召回评测需要分别记录字典、树、全文和语义后备的增量贡献，并以无 Embedding 路径作为持续可用的基线。

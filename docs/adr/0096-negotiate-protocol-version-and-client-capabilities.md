# 协商运行协议版本与客户端能力

V2 本地核心公开由主版本和次版本组成的 `protocol_version`，入口适配器连接时声明支持范围及证据展开、批次审阅、迁移包等可选能力。主版本不兼容时，核心拒绝语义写操作并返回明确升级诊断，不允许适配器退化为直接访问 SQLite；次版本新增字段保持向后兼容，但旧入口不得批准自己无法表达或理解执行效果的提案。

审阅决定、知识修订和胶囊维护等写操作携带 `expected_version`，由核心执行乐观并发检查。MCP 与 CLI 使用相同的领域消息和 JSON Schema，CLI 作为协议兼容性诊断及自动化验收基准。迁移包拥有独立格式版本，导入前仍必须 dry-run，不能用运行协议版本替代数据交换兼容检查。

## Consequences

各智能体入口可以独立升级而不绑定内部数据库布局，版本错误会在写入前失败。仓库需要保存机器可读 Schema、兼容矩阵和契约测试，并明确区分未知展示字段与未知语义效果。

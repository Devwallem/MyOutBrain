# 分离持久变更审计与紧凑召回日志

V2 使用两类互不替代的日志。永久审计日志记录审阅决定，规范记忆、来源关系及生命周期状态的版本变化，以及迁移包导入导出、永久删除、垃圾回收、修复、数据库升级和胶囊重组结果，用于回答谁在何时改变了什么。

每次知识召回另写一条紧凑召回日志，保存 `recall_id`、时间、入口、任务标识、使用的字典、分区树、局部或全库 FTS、可选 Embedding 路径，最终选中的 `memory_id`、版本与状态，召回字节数、证据是否展开、可回答性结果，以及越区命中、歧义、缺失依赖和冲突信号。它不复制用户完整问题、知识正文、答案或证据正文。单次事件默认长期保留，可以按月压缩物理表示但不能丢失事件；使用次数、最近召回和路由失败趋势均为可重建视图。

召回日志只能支持观察、诊断和不改变语义的路由优化，不得成为知识权重、可信状态、自动修订或用户偏好的隐性来源。短期详细诊断日志仍默认关闭并可直接删除。

## Consequences

创作者既能审计知识变化，也能看到知识库如何参与实际工作。存储随召回次数线性增长，但每条记录保持紧凑且不重复正文；实现需要将审计、召回活动和可丢弃运行遥测分别存放，并提供按时间、知识和入口查询的活动视图。

# 保持审阅呈现形式与客户端无关

V2 只定义审阅呈现契约和审阅批次语义，不规定各 App 的界面形式。Codex、OpenCode、Claude Code 或其他入口可以使用自然对话、表格、TUI、网页或可重建 Markdown/Obsidian 视图，只要内容足以清楚表达提案、证据、冲突、批准效果和可用动作，并把决定提交到本地核心的同一审阅批次。大量提案可以使用专门视图辅助，但 V2 不要求独立审批后台。

## Consequences

入口适配器可以利用各自最合适的交互能力而不破坏可迁移性。展示顺序、折叠方式和视觉组件可以不同，稳定提案身份、版本预期和决定结果必须一致，客户端不能保存另一套待审状态。

# 02 — 从来源批准第一条规范记忆

**What to build:** 创作者可以提交一份本地来源，审阅一个最小整合提案，并在批准后得到第一条带来源的规范记忆、知识字典入口和主知识胶囊记录。

**Blocked by:** 01 — 初始化并检查 V2 实例.

**Status:** resolved

- [x] 来源拥有稳定身份、版本、内容哈希和最低来源凭证。
- [x] 提交只创建待审整合提案，不直接修改规范记忆。
- [x] 批准后原子生成稳定 `memory_id`、当前版本、名称入口和唯一主胶囊记录。
- [x] 规范正文符合正文预算，超出内容留在证据层。
- [x] 重复批准通过幂等键返回同一结果，并记录紧凑审计事件。

## Comments

- 2026-07-18：新增 `propose-source-memory` 与 `approve-source-memory` 黑盒接缝。提交阶段只写入既有整合提案队列及最小来源凭证；来源正文不复制到数据库，凭证保留稳定 `source_id`、递增版本、SHA-256、定位符、观测时间和适用范围。调用者可用 `--source-id` 在来源移动或变化后延续同一稳定身份。
- 2026-07-18：显式批准在单次原子写入中形成稳定 `memory_id`、规范版本 1、知识字典名称指针、唯一主知识胶囊、证据关系、审阅记录和紧凑审计。审批要求 `expected_version=0` 和幂等键；同一请求重放返回逐字相同结果，冲突重用会被拒绝，故障注入后的恢复不会留下部分记忆。
- 2026-07-18：规范正文预算为 4096 字节目标、8192 字节硬上限；超限正文在提案阶段拒绝，来源余量继续只存在于证据层。新增 5 项端到端测试，并确认旧 `review-memory` 不能绕过来源审批约束。

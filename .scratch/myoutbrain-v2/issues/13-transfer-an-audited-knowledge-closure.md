# 13 — 迁移经审计的知识闭包

**What to build:** 创作者可以选择新增知识，审计其完整来源与知识依赖闭包，手动生成增量 ZIP，并在另一实例预览和幂等导入。

**Blocked by:** 05 — 复用重复来源并通过别名消歧; 06 — 修订、历史化、停用与永久删除知识; 07 — 完成统一审阅提案与批次决定.

**Status:** resolved

- [x] 导出计算选中知识的传递证据与知识依赖闭包。
- [x] 任一依赖受限、缺失或无法审计时阻止整个导出并报告路径。
- [x] 普通 ZIP 包含版本清单、稳定身份、对象、关系和迁移检查点，不复制 SQLite 内部布局。
- [x] 目标导入前完成 dry-run、哈希与版本检查。
- [x] 同一包重复导入不产生重复对象、关系或知识版本。
- [x] 目标知识冲突只进入统一审阅提案，不自动覆盖。

## Answer

已通过 `MemoryGateway`、CLI JSON 与 V2.1 领域协议交付手动增量迁移 tracer bullet。导出会计算选中知识的全部版本、传递知识依赖、来源版本与证据关系，并对缺失精确版本、来源缺口、循环、无法审计及迁移限制按完整路径 fail closed。ZIP 只保存逻辑对象、稳定身份、关系、带对象哈希的版本清单和检查点，不暴露 SQLite 布局。

导入 dry-run 会复核格式/最低 Schema、清单与对象哈希、清单闭包与包内对象关系，并报告目标的新增、增量、精确复用、来源哈希复用和冲突。成功导入以包身份和期望检查点幂等；目标分歧先形成统一审阅提案且不推进检查点，批准后重试会把 incoming 版本映射到目标批准版本，再原子写入证据和知识关系，不自动覆盖目标历史。

验收覆盖 Codex、OpenCode 与 Claude Code 的同一网关契约。严格 mypy 通过；迁移黑盒 12 项、相关回归 57 项及完整 249 项测试全部通过；最终 Standards/Spec 双轴复审均无 findings。

## Comments

- 工单范围保持为手动 ZIP 迁移；未加入远程传输、安全隔离、自动同步或工单 15 的能力。

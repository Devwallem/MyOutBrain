# 09 — 发现反证并在审阅前保持知识不变

**What to build:** 当本地材料或公开查询发现反证时，系统立即阻止无冲突结论并递交统一审阅提案，但在创作者决定前不改变任何持久知识状态。

**Blocked by:** 04 — 知识不足时补充公开证据或保持未知; 06 — 修订、历史化、停用与永久删除知识; 07 — 完成统一审阅提案与批次决定.

**Status:** resolved

- [x] 反证来源进入当前召回包并使二元可回答性失败。
- [x] 系统创建关联知识、来源、作用范围和当前任务的整合提案。
- [x] 提案待审期间知识版本、生命周期、来源关系和当前基线均不改变。
- [x] 批准后只能通过既有修订、取代、历史化、停用或并列冲突路径改变知识。
- [x] 拒绝反证保留审阅决定与来源关系，不以多数来源自动裁决。

## Answer

已完成反证统一审阅 tracer bullet。CLI 与 MemoryGateway 现可把本地或公开反证路由到一次既有召回：反证凭证进入召回延续包，核心在发现它的当前任务内强制 `unresolved-conflict`，并创建关联目标知识/版本、规范 Source/SourceVersion、作用范围、任务与 recall 的 blocking `integrate` 提案。待审期间只新增来源凭证、审阅提案和召回活动，规范知识版本、生命周期、知识—来源关系与共同基线正文保持不变。

批准反证通过既有 `revise_canonical_memory` 物化并建立新版本的规范 `supports` 来源边；工单 05 留给本工单的冲突提案批准边界同步完成。拒绝项保留终态决定和反证来源，相同来源在新 recall 中重报不会自动恢复；多条来源只合并凭证，不触发多数裁决。公开反证使用 receipt-only 展开，schema 9 无损升级为 schema 10 以正式支持 public Source。

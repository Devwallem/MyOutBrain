# 04 — 把缓冲记忆提议并批准为规范记忆

**What to build:** 让用户手动发起一次整合，将相关缓冲记忆与既有内容组织成少量自然语言提案，并通过自然审阅接受、编辑或拒绝；只有批准结果才会事务性地成为规范记忆。

**Blocked by:** 02 — 通过记忆网关召回缓冲内容.

**Status:** resolved

- [x] 手动整合会召回相似的新旧内容，并按主题生成少量提案而不是逐条制造审批负担。
- [x] 每个提案展示拟议理解、依据、来源范围、相关既有记忆和可能影响。
- [x] 用户可通过自然语言接受、编辑或拒绝提案，不需要操作数据库字段或固定分类表单。
- [x] 未审阅提案不会修改规范记忆；拒绝提案会保留审计结果但不会产生规范语义。
- [x] 接受或编辑后的结果以稳定身份、来源链接和审阅决定事务性写入规范记忆。
- [x] 确定性去重和索引维护可以自动完成，但不得借维护过程改变长期语义。
- [x] 原始证据在整合前后保持不变，规范内容只引用证据。
- [x] 中断或失败只留下完整旧状态或完整新状态，不会留下部分批准结果。

## Answer

已在 `LocalMemoryCore` 与 CLI 主验收入口中完成手动记忆整合。`consolidate` 会在任务范围内批量召回缓冲简记与既有规范记忆，结合词法和本地 Embedding 候选按主题形成少量待审提案；默认文本和 JSON 均展示拟议理解、依据、直接来源、相关规范记忆及明确影响。Embedding 不可用时安全回退到词法候选，重复运行会复用稳定提案而不会改变规范语义。

`review-memory` 支持自然中英文接受、改写和拒绝，并提供待审队列与审阅历史。未审阅和拒绝不会产生规范语义；接受或编辑通过单写入锁和可恢复原子提交写入 SQLite、来源关系与追加审计。完全重复的内容复用既有规范身份并追加新来源，始终采用最严格敏感度；仅语义相关但不同的内容保留独立身份与持久关联，不会把旧记忆来源冒充为新内容证据，也没有提前实现 05 的版本/冲突语义。

数据库升级到 v3，并覆盖 v2 数据保留和升级后整合。中断注入验证批准过程只留下完整旧状态或完整新状态。最终 109 项测试、严格 mypy、编译检查、diff 校验以及 Standards/Spec 双轴复审均通过。

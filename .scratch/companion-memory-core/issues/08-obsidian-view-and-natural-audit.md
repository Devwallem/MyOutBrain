# 08 — 生成 Obsidian 知识视图并自然审计

**What to build:** 从规范记忆生成可读、可链接的 Obsidian 知识视图，让用户能够浏览和自然询问当前理解；视图被删除时可重建，人工修改则作为新证据返回统一审阅流程。

**Blocked by:** 05 — 修订知识并保留冲突与演变; 06 — 迁移现有 V1 永久知识.

**Status:** resolved

- [x] 规范记忆可生成包含稳定身份、当前理解、来源、版本与冲突摘要的 Obsidian 视图。
- [x] 生成过程不会把 Markdown 重新变成机器事实来源，也不会复制完整原始对话。
- [x] 删除全部生成视图后可以重建，重建前后的规范查询结果保持一致。
- [x] 视图中的链接和索引支持人类按主题浏览，而不要求用户维护细粒度固定分类。
- [x] 用户对生成视图的修改会被识别为新证据并进入缓冲与提案审阅，不会直接覆盖规范记忆。
- [x] 用户能够通过自然查询查看某项理解的来源、确认状态、演变与冲突。
- [x] Obsidian 不可用时核心记忆、召回和审阅仍能工作。
- [x] 使用确定性视图适配器的测试覆盖生成、删除重建、人工修改回流和失败隔离。

## Answer

已新增 `build-views`、`sync-view-edits` 与 `audit-memory` CLI。规范记忆在单一 SQLite 审计快照和单写入边界内投影为带稳定身份、来源、版本、确认状态、冲突链接和主题索引的 Obsidian 知识视图；视图及索引可删除重建，重建不改变规范查询结果。

人工修改通过内容哈希识别，先保存为本地经历与缓冲简记，再生成待审整合提案，不直接修改规范记忆。未同步修改会阻止重建；过时视图清理使用持久 `cleanup_paths`，中断后可幂等恢复。清单路径限制在解析后的托管目录内，并兼容原生及迁移后的稳定身份。Obsidian CLI 缺失只产生警告，不影响核心记忆、召回或审阅。

# 05 — 修订知识并保留冲突与演变

**What to build:** 让后续整合能够在稳定知识身份下补充或修订当前理解，保存旧版本和变化原因，并在证据尚不能消除分歧时并列保留冲突，而不是制造重复记录或虚假确定性。

**Blocked by:** 03 — 召回措辞不同但语义相近的记忆; 04 — 把缓冲记忆提议并批准为规范记忆.

**Status:** resolved

- [x] 整合提案可明确表示新增、补充、修订或保留冲突，并引用候选相似内容与原始证据。
- [x] 批准的修订沿用稳定知识身份，当前版本可查询，旧版本和替代原因可审计。
- [x] 相近但证据不足以合并的内容不会仅因语义相似而共享一个结论。
- [x] 未解决冲突并列存在并影响充分性判断，系统不会静默选择其中一方。
- [x] 已被替代的旧版本不会作为当前答案证据，但仍可通过演变历史查看。
- [x] 用户可以自然询问“为什么这样认为”，并获得当前确认状态、关键来源、版本变化和未决冲突。
- [x] 召回评估覆盖过时知识、未决冲突和已替代版本。
- [x] 失败的修订不会破坏此前已确认的当前版本。

## Answer

已将规范记忆数据库升级到 v4，加入稳定身份下的版本链、逐版本来源、变化原因和未决冲突。整合提案与审阅结果现在明确记录新增、补充、修订或保留冲突；完全重复仍只追加来源，补充与修订在原知识身份下生成新当前版本，旧版本记录退出时间与替代原因，语义相近但未经创作者决定的内容不会自动合并。

`review-memory` 支持自然中英文修订、补充和保留冲突指令。补充保留前一版本及新证据，修订只让新版本来源进入当前证据包，历史来源继续留在审计中；保留冲突会创建独立规范身份和持久冲突对。记忆网关召回冲突一方时会同时带回可见的另一方并保持 `insufficient`，公共访问不会泄露 `local-only` 冲突身份。

新增 `why-memory` 认知审计入口，可查看当前确认状态、当前版本、关键来源、完整演变与未决冲突。v3 规范记忆可迁移并回填为版本历史，v2 仍可连续升级。版本化召回基线现在把未决冲突标为必须拒绝，并继续排除已替代证据。故障注入验证失败修订会恢复旧当前版本和待审提案。最终 114 项测试、严格 mypy、编译与 diff 校验均通过。

# 06 — 迁移现有 V1 永久知识

**What to build:** 将现有 V1 的来源、派生洞见、个人认知与审计事件迁移到新的规范事实来源，使已有知识继续可查、可追溯、可重建，同时停止把旧 Obsidian Markdown 当作机器唯一真相。

**Blocked by:** 05 — 修订知识并保留冲突与演变.

**Status:** resolved

- [x] 迁移前能够识别现有模式版本并选择正确迁移路径，未知或不兼容版本会安全停止。
- [x] 来源对象保持内容寻址与去重，既有稳定标识、来源链接、确认状态和事件尽可能原样保留。
- [x] 已批准洞见和个人认知迁移为带版本的规范记忆，候选或未确认内容不会被错误晋升。
- [x] 迁移可重复执行且结果幂等，不会制造重复知识、重复正文或重复版本。
- [x] 迁移失败不会修改旧事实来源或留下一个被误认为完成的新实例。
- [x] 迁移后，现有初始化、采集、隐私、锁、审计、提供方失败和重建行为继续通过验收测试。
- [x] 新核心能够在不读取旧 Markdown 真相的情况下回答等价查询并说明原有来源。
- [x] 迁移完成状态和审计摘要可由 CLI 查看。

## Answer

已实现 `migrate-v1` 与 `migration-status` CLI。迁移在单一 writer lock 下验证 V1 来源、Vault 关系和审计日志，生成 fingerprint，并将内容寻址来源、来源元数据、已批准洞见、个人认知、版本、状态、关系元数据及原始审计事件原子写入 SQLite；未知版本、输入变化和故障均安全停止。重复执行相同输入返回 `already-complete`，停用知识不参与召回但仍可由 `why-memory` 按稳定 ID 审计。

验收结果：122 个单元测试通过，strict mypy 通过，compileall 通过；Standards 与 Spec 双轴复审均无剩余发现。实现提交为 `fd7ac84` 与 `396de2e`。

# 09 — 停用、永久删除并报告存储占用

**What to build:** 让用户通过自然命令停用或永久删除记忆，并能查看证据、规范记忆、缓冲区与可重建索引各自的存储占用，从而控制隐私和增长而不误删原始证明。

**Blocked by:** 05 — 修订知识并保留冲突与演变; 06 — 迁移现有 V1 永久知识.

**Status:** resolved

- [x] “忘掉”默认停用目标记忆，使其不再参与普通召回，同时保留可逆状态、来源和审计记录。
- [x] 只有明确的永久删除意图才会删除目标来源、派生摘要、规范版本、关系和未来备份范围。
- [x] 永久删除前展示影响范围并要求明确确认，模糊或范围过大的请求安全停止。
- [x] 删除后通过普通查询、全文索引、语义索引、Obsidian 视图和待处理提案均无法重新暴露目标内容。
- [x] 可重建产物会同步清理或标记重建，内容寻址对象仅在不存在其他有效来源关系时移除。
- [x] 存储报告分别展示原始证据、规范记忆、缓冲内容和可重建索引的体积与数量。
- [x] 容量维护不会自动删除大型原始证据；任何破坏性优化都需要用户批准。
- [x] 验收测试覆盖可逆停用、共享正文保留、永久级联删除、索引重建后仍不可召回和分层存储报告。

## Answer

已实现 `forget-memory` 的可逆停用/恢复、`delete-memory` 的有界影响预览与精确确认，以及 `storage-report` 的证据、规范记忆、缓冲区和可重建索引分层统计。

永久删除会级联移除目标规范版本、非共享来源、派生简记、关系、冲突和目标整合审计；共享来源及其他记忆审计保留。数据库变更、事件日志脱敏和持久化清理清单原子提交，进程中断后会在下一次正常操作前继续清理内容对象、Obsidian 视图及全文/语义索引。删除标记阻止旧证据重新导入；未来备份从删除时点排除目标，既有外部备份需由所有者明确轮换或删除。

验收覆盖可逆停用、精确确认、完整级联、共享正文与审计保留、中断恢复、视图/索引重建不复现、再次导入阻断和分层存储报告。

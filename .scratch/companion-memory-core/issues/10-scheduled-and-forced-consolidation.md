# 10 — 定时整合、受限云端分析与本机通知

**What to build:** 在手动整合之外提供定时和紧急强制整合；定时任务可以在可撤销的持续授权内使用云端分析，但只能生成待审阅提案，并在无活跃对话时通过本机通知提示用户。

**Blocked by:** 05 — 修订知识并保留冲突与演变.

**Status:** resolved

- [x] 用户可以手动、按明确计划或为紧急任务强制启动整合，系统不会自行猜测空闲状态或剩余额度。
- [x] 强制整合可以在重要回答前处理相关缓冲内容，但仍须遵守语义提案与人工批准边界。
- [x] 定时云端授权固定提供方、模型、允许敏感度、批大小、令牌上限和费用上限，并可随时撤销。
- [x] `local_only` 内容始终排除在云端批次外，越权、超批或超预算请求不会发出。
- [x] 无论本地还是云端分析，语义结果只能生成提案，不能自动修改规范记忆。
- [x] 确定性去重与索引维护可自动提交，并与语义变化审计清楚区分。
- [x] 完成的提案在有活跃对话时立即交付；无活跃对话时进入待审阅队列并发送本机通知。
- [x] 使用确定性能力与通知替身的测试覆盖计划触发、授权边界、失败重试、提案只读和通知交付。

## Answer

已实现显式手动、紧急强制和周期计划三种整合入口；`answer --force-consolidation` 会在重要回答前为任务相关缓冲内容准备待审提案，但不会自动修改规范记忆。计划运行使用进程级独占锁、版本化运行身份、可恢复尝试状态和计划 CAS，进程中断、同时间计划修订及授权撤销后仍能安全恢复已落盘提案。

定时云端分析受可撤销授权约束，固定提供方、模型、敏感度、批大小、完整请求令牌上限和费用上限。每次派发前先持久化证据 ID、目的和最大预算，返回后记录实际 token、费用及结果；失败、超界和中断同样保留可恢复审计，`local-only` 内容不会进入云端批次。

无活跃对话时，强制与定时提案统一进入持久待审队列和通知 outbox；本机通知使用稳定幂等 ID，失败可显式重试。确定性索引维护与语义提案分开审计。验收覆盖授权/预算边界、并发与崩溃恢复、提案只读、活跃/离线交付及通知重试。

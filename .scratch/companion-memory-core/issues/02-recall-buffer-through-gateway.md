# 02 — 通过记忆网关召回缓冲内容

**What to build:** 让 CLI 和首个程序化记忆网关针对当前任务请求最小证据包，并能通过稳定关系与本地全文检索召回尚未整合的缓冲记忆和已有规范记忆，而调用方无需知道存储实现。

**Blocked by:** 01 — 记录一段对话为缓冲记忆.

**Status:** resolved

- [x] 记忆网关提供任务范围的查询入口，并返回内容、状态、来源、时间、敏感度和稳定身份所需的最小证据。
- [x] 刚提交的缓冲摘要无需先整合即可在后续相关查询中被召回。
- [x] 已知身份和来源关系优先通过确定性关系召回，名称与精确措辞可通过本地全文检索召回。
- [x] 规范记忆与缓冲记忆在结果中可区分，缓冲内容不会伪装成已确认事实。
- [x] 网关执行固定的本地可信、任务范围、公开外部三级访问约束，任务查询不会获得无关私人证据。
- [x] 实质性问题会先查询共同知识基线；闲聊和简单操作可跳过不必要召回。
- [x] 没有充分证据时返回明确的“不足”信号，而不是用局部命中拼成完整答案。
- [x] CLI 与网关接口测试证明调用方不依赖数据库、全文索引或对象存储细节。

## Answer

已新增程序化 `MemoryGateway.recall` 与 `myoutbrain recall` CLI。网关按规范记忆基线、缓冲简记两个阶段查询，稳定记忆 ID 与来源关系优先于本地 SQLite FTS5 全文候选；英文名称、中文精确短语和最低词项覆盖共同约束最小证据包。返回项包含稳定身份、内容、规范/缓冲状态、确认状态、来源、时间、敏感度、入口、任务与匹配路径，且不暴露数据库、全文索引或对象路径。三级权限会限制任务范围并让 `local-only` 采用最严格来源敏感度；闲聊与简单操作跳过检索，实质问题在缺少完整时效、冲突和来源质量判定前保守返回 `insufficient`。SQLite 模式已通过可恢复迁移升级到 v2，为规范记忆补齐状态、敏感度和来源关系。新增 8 个网关/CLI 场景；完整 90 项测试、严格 mypy、编译检查及 Standards/Spec 双轴审查均通过。

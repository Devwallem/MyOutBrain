# 01 — 记录一段对话为缓冲记忆

**What to build:** 让用户能够初始化一个与公开程序分离的私人实例，并通过 CLI 将当前可见对话作为一份可追溯经历提交到本地核心；系统只保存一份原始正文，同时生成一条可立即使用但尚未成为规范知识的紧凑缓冲记忆。

**Blocked by:** None — can start immediately.

**Status:** resolved

- [x] 初始化会创建带模式版本的私人实例，重复初始化不会覆盖已有内容，也不会隐式创建或发布 Git 历史。
- [x] CLI 可以提交正文、时间、入口、任务、敏感度、可见上下文和明确的上下文盲区。
- [x] 相同正文从不同任务或入口重复提交时只保存一份内容对象，同时保留各自的来源关系。
- [x] 每次有效提交至多产生一条通用紧凑摘要，摘要引用原始证据而不复制完整对话。
- [x] 新摘要处于缓冲状态，与规范记忆明确分离，并留下可审计事件。
- [x] 提交失败或被中断时，不会留下正文、摘要和来源关系彼此不一致的部分状态。
- [x] CLI 验收测试覆盖首次初始化、重复初始化、内容去重、敏感度与盲区记录，以及失败回滚。

## Answer

已新增版本化 SQLite 本地记忆核心与 `myoutbrain remember` CLI。提交入口提供当前可见对话和紧凑语义简记，本地核心验证简记不复制完整正文并追加稳定来源指针；正文按 SHA-256 只保存一份，不同任务或入口分别保留经历关系。经历元数据、缓冲简记和审计事件与内容对象通过同一可恢复事务原子提交，缓冲状态与规范记忆明确分离。新增 7 个 CLI 场景覆盖初始化、语义简记、正文去重、幂等重试、敏感度、上下文盲区、输入验证和故障回滚；完整 82 项测试、严格 mypy、编译检查与 Standards/Spec 双轴审查均通过。

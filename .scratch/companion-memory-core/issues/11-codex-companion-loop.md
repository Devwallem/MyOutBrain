# 11 — 连接 Codex 并验证完整同伴闭环

**What to build:** 让 Codex 作为第一个智能体入口，通过统一记忆网关在回答前获取任务相关证据、在回答后提交实际可见经历，并用 CLI 演示从接收、召回、研究、回答、写回、审阅到再次召回的完整同伴闭环。

**Blocked by:** 07 — 知识不足时检索公开信息; 08 — 生成 Obsidian 知识视图并自然审计; 09 — 停用、永久删除并报告存储占用; 10 — 定时整合、受限云端分析与本机通知.

**Status:** resolved

- [x] Codex 入口在实质性问题前请求任务范围的最小证据包，并遵守闲聊跳过与三级访问约束。
- [x] Codex 只提交当前实际可见上下文、稳定任务指针和明确盲区，不声称读取不可见历史。
- [x] Codex 与 CLI 的所有长期写入都经过同一个记忆网关，不产生入口专属的孤立用户模型。
- [x] 更换确定性能力引擎后，记忆身份、来源关系、已批准知识和可召回结果保持连续。
- [x] 完整演示覆盖：接收新知识、立即缓冲召回、内部不足、脱敏公开补充、可追溯回答、缓冲写回、整合提案、自然批准和未来再次召回。
- [x] 完整演示同时覆盖检索后仍不足时保持未知，以及未批准提案不改变规范记忆。
- [x] 删除所有可重建索引与 Obsidian 视图后，重建仍能通过同一完整闭环验收。
- [x] 第一阶段文档说明模型与入口是可替换能力，明确人格、情绪、多媒体和自主网络学习仍属后续范围。

## Answer

已增加 Codex 智能体入口与 `codex-context`、`codex-submit` CLI：实质任务开始前只经统一 `MemoryGateway` 请求任务范围的最小证据包，闲聊可跳过召回；结束后只把当前可见文本、稳定任务指针、摘要与明确盲区提交到同一个记忆核心。既有 CLI、回答写回和知识视图编辑产生的经历也统一改走该网关，没有 Codex 专属用户模型。

仓库内提供 `myoutbrain-companion` Codex Skill 和第一阶段闭环文档。Skill 把 Codex 定义为可替换能力引擎，禁止直接读取私人实例内部存储，也禁止为让回答成功而放宽本地敏感度或擅自授权云端；当前任务与返回证据充分时直接作答，需要标准化公开补充时才使用脱敏查询。

端到端验收覆盖新知识接收、即时缓冲召回、内部不足、脱敏公开研究、可追溯回答与写回、整合提案、自然批准、未来召回、检索后保持未知、未批准提案隔离、确定性能力引擎替换，以及删除并重建语义索引和 Obsidian 视图。记忆 ID、来源 ID 和已批准内容在上述替换与重建后保持连续。

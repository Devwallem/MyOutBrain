# 03 — 基于证据包回答材料问题

**What to build:** 让单一创作者可以通过 `ask` 对已采集的 Markdown 提问，获得以最小证据包为依据、可回到原始材料核验的回答，同时严格执行云端授权、敏感级别和外发审计。

**Blocked by:** 02 — 幂等采集 Markdown 原始材料

**Status:** resolved

- [x] `ask` 能针对已采集的单篇 Markdown 形成最小证据包并返回自然语言回答
- [x] 回答中的关键结论关联稳定来源身份和人类可核验的来源定位
- [x] 当材料不能回答问题时，系统明确说明证据不足，而不是依靠模型常识猜测
- [x] 新项目使用提供方中立的生成接口，首个真实适配器通过 OpenAI Responses API 工作
- [x] API 凭据仅从进程环境或操作系统凭据机制获得，不出现在仓库、Vault、输出或普通日志中
- [x] 每次云端调用都要求当次明确授权；过去的授权不会自动沿用
- [x] `local-only` 内容在任何情况下都不会传给生成适配器，缺失或无效的敏感级别不会被静默视为可外发
- [x] 生成适配器只能收到证据包而不能读取整个 Vault 或永久对象存储
- [x] 每次外发记录时间、提供方、模型、目的、来源身份和非敏感请求指纹，但不复制完整原文
- [x] 提供方超时、拒绝或返回无效结果时，命令返回稳定错误且不改变永久知识
- [x] 验收测试使用确定性假生成适配器检查确切外发内容；真实 OpenAI 适配器仅通过独立契约测试验证转换

## Answer

已实现从单篇已采集 Markdown 构造最小证据包的 `ask` 工作流。回答采用逐条结论结构，每条结论必须携带当前证据包内的稳定来源身份与行定位；证据不足时不输出模型猜测。云端调用要求当次 `--allow-cloud`，并在进入提供方前阻止 `local-only` 或敏感级别异常的材料。

生成层提供中立接口、确定性假适配器与 OpenAI Responses API 适配器。凭据只读取进程环境；外发审计只记录提供方、模型、目的、来源身份和请求指纹。超时、拒绝、无效结构以及越界引用均返回稳定的提供方错误，不修改永久知识。旧版配置缺少生成段时会使用默认 OpenAI 配置，并可通过重新初始化原样保留现有配置后补写默认段。

验收由 15 个 `ask` 测试覆盖；仓库全量 33 个测试、严格类型检查和字节码编译均通过。

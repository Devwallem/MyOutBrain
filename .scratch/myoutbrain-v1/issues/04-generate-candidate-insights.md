# 04 — 从证据生成候选洞见

**What to build:** 让单一创作者可以通过 `reflect` 请求系统审视已采集材料，并得到可批判检查、不会自动污染永久知识的候选洞见。

**Blocked by:** 03 — 基于证据包回答材料问题

**Status:** resolved

- [x] `reflect` 使用证据包生成候选洞见，而不是直接写入 Obsidian 永久知识
- [x] 每个候选洞见包含支持证据、发现时的反对证据、推导摘要和稳定候选身份
- [x] 候选记录明确标记为系统产生且尚未经创作者审阅
- [x] 候选只存在于可回收工作区，并携带可配置的过期信息
- [x] 材料上等价或高度相似的候选被合并，而不是反复保存正文副本
- [x] 合并候选会累计出现次数和最近出现时间，使重复出现可见
- [x] 已拒绝候选的轻量指纹能够抑制立即重复生成，同时不永久保留不必要正文
- [x] 生成失败、证据不足或工作区写入失败时，不产生部分候选或永久知识变化
- [x] 验收测试证明多次反思不会造成候选数量按调用次数无界复制

## Answer

已实现 `reflect` 命令：它复用受云端授权与敏感级别保护的最小证据包，通过提供方中立的文本生成接口产生候选洞见。每条候选包含稳定身份、系统作者属性、待审状态、支持与反对证据、推导摘要、出现次数、最近出现时间和可配置过期时间；任何候选都不会写入 Obsidian 或永久知识记录。

候选工作区以单一原子 catalog 管理。相同或高度相似的中英文候选会在同一次响应及后续反思中合并，累计 recurrence，合并新增证据并更新推导；多次调用不会按调用次数复制正文。近期拒绝指纹只保存哈希与抑制期限，不保留候选正文。

提供方失败、证据不足、越界引用和写入中断均不会留下部分候选。确定性假适配器验证确切外发证据包，OpenAI Responses 适配器由本地契约服务器验证转换，不执行真实云端调用。

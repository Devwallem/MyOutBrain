# 05 — 审阅并晋升衍生洞见

**What to build:** 让单一创作者可以通过 `review` 查看候选洞见，选择编辑后接受、直接接受、暂缓或拒绝，并把值得长期保留的内容晋升为可在 Obsidian 中维护的衍生洞见。

**Blocked by:** 04 — 从证据生成候选洞见

**Status:** resolved

- [x] `review` 能列出待审候选及其支持证据、反对证据、推导摘要和重复次数
- [x] 用户可以直接接受候选，结果成为 `kind: insight` 的永久知识笔记
- [x] 用户可以先编辑候选再接受，永久笔记准确记录用户与系统的作者属性
- [x] 用户可以暂缓候选而不改变其内容和晋升状态
- [x] 用户可以拒绝候选，候选从活跃审阅中移除并留下轻量抑制指纹
- [x] 被接受的知识笔记具有稳定身份、活动状态、敏感级别、时间、来源身份和演变元数据
- [x] 接受候选只会生成衍生洞见，不能在同一动作中成为个人认知
- [x] 每次审阅决定写入永久知识演变事件，失败时不会出现事件与知识状态不一致
- [x] 成功接受后通过 Obsidian CLI 适配器尝试打开知识笔记；Obsidian 不可用时保留有效写入并给出警告
- [x] Obsidian Markdown 在 MyOutBrain 或 Obsidian CLI 不运行时仍可由人直接阅读和编辑
- [x] 所有永久写入使用项目锁和原子替换，非法状态转换不产生任何修改

## Answer

已实现 `myoutbrain review` 的候选列出、暂缓、拒绝、直接接受和编辑后接受。接受操作在项目锁内通过可恢复多文件事务同时更新候选目录、普通 Obsidian Markdown 知识笔记和永久演变事件；成功提交后由 Obsidian CLI 适配器打开笔记，CLI 缺失或失败只产生警告。拒绝仅保留带期限的轻量指纹，接受始终生成衍生洞见且不会成为个人认知。

验收测试覆盖作者属性、稳定元数据、非法目标零修改、抑制重复、Obsidian 命令契约及两个多文件中断恢复边界。

# 06 — 显式晋升个人认知

**What to build:** 让单一创作者通过与候选审阅分离的明确操作，将本人真正认可的衍生洞见晋升为个人认知，并在观点改变时保留可追溯的认知演变。

**Blocked by:** 05 — 审阅并晋升衍生洞见

**Status:** resolved

- [x] 只有用户明确发起的晋升操作才能把衍生洞见变为个人认知
- [x] 生成适配器、反思逻辑和候选审阅动作都无法绕过该人工晋升步骤
- [x] 晋升目标必须是有效且活动的衍生洞见，其他类型或状态返回稳定错误且不修改数据
- [x] 晋升结果使用 `kind: cognition`，并如实保留原始来源、系统参与和用户认可信息
- [x] 用户可以用新个人认知取代既有认知，旧认知变为 `superseded` 而不被删除
- [x] 新旧认知记录双向可追溯的取代关系，重命名知识笔记不会破坏关系
- [x] 晋升和取代写入知识演变事件，并在中断时保持原子一致
- [x] 验收测试覆盖允许与禁止的全部状态转换，特别证明 AI 内容绝不会自动成为用户立场

## Answer

已实现独立的 `myoutbrain promote` 用户操作。活动衍生洞见会生成具有新 `cog_` 稳定身份的个人认知，原洞见归档但保留；个人认知以 `mixed` 作者属性、`derived_authorship`、`endorsed_by` 和 `endorsed_at` 明确区分系统参与与用户认可，并通过普通 Markdown、稳定 ID 和双向 wikilink 保持可读可追溯。

`--supersedes` 可以让新认知取代按稳定 ID 定位的活动旧认知，即使旧笔记已经重命名；旧认知变为 `superseded`，双方记录稳定 ID 关系，晋升与取代分别写入演变事件。所有相关 Vault 笔记和事件通过项目锁下的可恢复多文件事务提交，成功后尝试在 Obsidian 中打开新认知。

验收测试覆盖直接晋升、重命名后的取代、无效元数据、缺失或错误类型与状态、无效取代目标，以及晋升和取代各写入边界的硬中断恢复。

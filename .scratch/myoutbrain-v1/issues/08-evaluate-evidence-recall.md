# 08 — 建立证据召回评测

**What to build:** 让单一创作者可以运行一套小型、可重复的证据召回评测，单独判断系统是否选中了正确材料，并以真实失败决定未来是否需要嵌入、重排或其他 RAG 能力。

**Blocked by:** 06 — 显式晋升个人认知

**Status:** resolved

- [x] 评测数据能够表达问题、预期来源、是否可回答以及案例类别
- [x] 基线评测至少覆盖可回答、不可回答、观点冲突和已被取代认知四类案例
- [x] 评测把证据选择结果与最终回答文风分开报告，模型猜对不能掩盖错误召回
- [x] 报告清楚列出正确命中、关键遗漏、错误引用和应拒答却回答的案例
- [x] 评测可以重复运行并产出适合人阅读和后续自动比较的结果
- [x] 默认评测不依赖实时云端模型，避免模型波动掩盖检索变化
- [x] 当前无嵌入基线得到明确记录，后续只有观察到持续召回失败时才引入更复杂检索
- [x] 增加未来检索适配器时可以复用同一评测集进行前后对比，而无需重写问题定义

## Answer

已实现 `myoutbrain evaluate-recall`。版本化 JSON 评测集显式记录原始材料或个人认知、活动或已取代状态、问题、案例类别、是否可回答和预期证据；仓库基线覆盖可回答、不可回答、观点冲突和已取代认知四类案例。

评测默认使用离线 `lexical-no-embeddings` 适配器，不调用生成模型。共享 `EvidenceRetriever` 契约返回证据选择与独立的应拒答决定，因此相关证据的存在不会被误当成已经回答；未来词法、嵌入或重排适配器可以直接复用相同数据集。

命令提供稳定 JSON 和人读文本报告，逐案例与汇总列出正确命中、关键遗漏、错误引用和应拒答违规；失败时返回非零退出码，便于自动回归比较。75 个 CLI 回归测试和严格类型检查通过，当前四案例基线全部通过，尚无证据支持引入嵌入或完整 RAG。
